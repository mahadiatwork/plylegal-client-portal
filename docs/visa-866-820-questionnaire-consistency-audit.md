# 866 and 820 questionnaire consistency audit against approved 482 and 186

**Date:** 8 September 2026  
**Repository revision:** `6d2aa87`  
**Deliverable:** historical comparison and recommended changes at the revision above.  
**Implementation update:** the authorised changes have now been implemented. See [the implementation and validation report](visa-866-820-questionnaire-alignment-implementation.md). Findings and source-line references below describe the pre-change snapshot.

The 866 Protection and 820 Partner questionnaires are **partly aligned, but not yet consistent** with the current client-approved 482 Skills in Demand and 186 Employer Nomination questionnaires. Some pages already share the approved code. Other pages retain older prompts, different option lists, and different conditional forms.

This report uses the **current implementation** of 482/186 as the reference, as requested. Earlier audit documents and the old portal are not treated as approved wording. A difference between visa subclasses is a change candidate only when the question asks for the same information from the same person over the same period.

## How to read the audit

| Classification | Meaning and action |
|---|---|
| **Same / already aligned** | Displayed text or the specified option set matches the approved equivalent. Keep it. A row may describe several explicitly listed fields or repeated instances of the same question. |
| **Change wording / options** | A meaningful approved equivalent exists. Use the exact reference text or options shown in the comparison. Preserve the person the question refers to. |
| **Structure / scope decision** | The forms differ in who answers, time period, categories, conditions, or information collected. Align presentation where possible, but decide the intended coverage before adding, removing, or merging fields. |
| **No approved equivalent / visa-specific** | The active 482/186 questionnaire does not ask an equivalent question. Keep the target question separate; absence from an employer-sponsored form is not a reason to remove it. |
| **Auxiliary / outside normal flow** | A source page exists but is not generated in the normal questionnaire sequence. Its findings are recorded separately from active questions. |

“Same” compares rendered wording, normalising source whitespace, JSX entities such as `&amp;`, and decorative required markers. It does not by itself claim identical data storage, validation, document requirements, or layout. Short changed option lists are written out. Shared country/date lists are identified by source and differences, rather than repeating the same long list for every field. Repeated person fields are grouped explicitly; route counts are not presented as question counts.

## Recommended change order

1. **Apply exact copy corrections for established equivalents.** Start with the common Character declarations, the 820 classroom prompt and other matching health gates, employer/occupation labels, standard personal/contact labels, and 866 Other Names/navigation captions. The tables supply the current and reference wording.
2. **Align equivalent option lists.** Address the missing gender option, truncated country list, 820 healthcare-role typo/duplicate, education course-status wording/order, and other short enums identified below. Preserve existing stored answers when options are renamed or replaced.
3. **Resolve changes to information collected.** Decide the intended treatment of broader citizenship history, absent spouse/child fields, target-only Character prompts, split health/character answers, different travel/residence periods, and sponsor/relationship questions. These cannot be resolved reliably by string replacement alone.
4. **Align the surrounding form behaviour where requested.** Follow-up layouts, applicant selectors, optional/ongoing dates and submission blocking must agree with the wording presented to the client.
5. **Keep the existing exact matches.** Reuse the approved shared components and preserve subclass-specific parameters. The accepted 482/186 content does not need to be rewritten to make the target visas consistent.
