Create a production-ready (validation phase) Next.js 14 (App Router) + TypeScript app called “Ply Legal — Client Portal”. It implements a mobile-first multi-step intake wizard with the exact page tree, fields, gates, repeaters, and validations described below.

Routing and navigation

Each bullet in the PAGE TREE below is its own route under /intake/<section>/<subpage>.

WizardShell renders a sidebar stepper (desktop) and top tabs/dropdown (mobile).

Show current section + subpages as chips/tabs under the section title.

Sticky bottom bar (mobile): “Previous”, “Save Draft”, “Continue” (≥44px targets).

Show progress bar (percent of subpages completed).

On page change: scroll to top, run validation for current page, autosave draft.

Dummy login (no backend)

Route: /login

Prefilled credentials: user@example.com / password123

On submit, set localStorage['ply_session']="ok" and redirect to /intake/start.

If session missing and user visits /intake/*, redirect to /login.

Draft persistence, autosave, toasts

Persist full Intake JSON in localStorage under key: ply:intake_draft

Autosave:

On every step change, and every 10 seconds while dirty.

POST same payload to /api/intake/save (stub) and show shadcn Toast “Draft saved”.

storage.ts exports: loadDraft(), saveDraft(partial), clearDraft() (merge semantics).

Repeaters (Add/Edit/Remove)

RepeaterTable:

Desktop: simple table with Add/Edit/Delete.

Small screens: render each row as a Card (stacked list) with action buttons.

Add/Edit opens shadcn Dialog with a mini form bound to RHF.

Persist immediately on submit; show micro fade/slide animations for row add/remove.

All Yes/No gates toggle the corresponding repeater visibility live.

Review & Submit

Route /intake/submit:

Render read-only summary grouped by section/sub-page, exact order as the page tree.

Each group has an Edit button linking back to that route and focusing the first field.

Submit posts full JSON to /api/intake/submit.

On success, show confirmation screen with reference like APP-#### and “Return to Start”.

Validation (Zod) — lib/validation.ts

Implement schemas per sub-page and export them. Highlights to enforce:

Required: family_name, given_names, gender, dob, country_of_birth, marital_status.

dob must be ≤ today, ≥ today − 100 years; must be ≥ 18 years old (error if under; or surface a warning string).

If has_other_names="Yes" ⇒ other_names.length ≥ 1 and all fields required.

If use_chinese_code="Yes" ⇒ chinese_code required.

If russian_descent="Yes" ⇒ patronymic_name.family_name & .given_names required.

If has_prev_dob="Yes" ⇒ prev_dobs.length ≥ 1.

If citizen_of_country="Yes" ⇒ citizenships.length ≥ 1.

If has_passport="Yes" ⇒ passports.length ≥ 1.

If has_identity_doc="Yes" ⇒ identity_docs.length ≥ 1.

Address rows require address and from; to (when present) must be ≥ from.

email (when provided) must be valid.

Travel: if any date present, departure_date ≥ arrival_date.

Character map: whenever an answer is Yes, require at least one detail object with a non-empty detail.

Use date-fns for date comparisons.
